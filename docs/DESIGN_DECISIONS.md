# Design decisions

All sample values and operational records in this project are synthetic. These decisions describe the bounded demonstration implementation, not real customer or contractor policy.

| Decision | Reason | Limitation |
|---|---|---|
| Retain distinct source envelopes in raw Delta and select current records by business key/revision | Replay, corrections, and investigations need preserved source versions and provenance | Local pipeline rewrites a deduplicated raw snapshot on each run; no streaming checkpoint or incremental merge path |
| Share Spark setup, raw replay merging, revision selection, freshness assessment, and local publication across examples | These mechanics apply to different source domains | Domain validation and reconciliation remain explicit code; this is not a no-code ingestion framework |
| Preserve the simpler allocation join until a stable measured benefit is established | In the local 10,000-line / 160,000-allocation profile, warmed median elapsed time changed from 190.40 ms to 188.08 ms; a later 50,000-line / 800,000-allocation profile measured 378.10 ms versus 328.70 ms | Both are synthetic microbenchmarks; hosted and end-to-end gains remain unmeasured |
| Store reporting products in generation-specific Delta paths and switch one pointer only after all writes | Readers must see a complete set of products | Local and bounded Databricks Unity Catalog volume runs retained the last complete pointer during an injected failure; other object-store semantics remain unverified |
| Keep invoice credits as positive source magnitudes with an explicit original-line reference, then negate once in the derived net amount | Preserve source document semantics and prevent double-negation | Initial link format is supplier/invoice/line identifiers; tax, freight, and complex credit pricing are out of scope |
| Keep source schema evolution strict for consumed fields and preserve additive fields | Prevent silent reinterpretation while allowing harmless additions | Automated schema registry and explicit cross-version mapping are not implemented |
| Do not configure automatic publication-history pruning | A prior published result must remain reproducible independently of Delta time travel | Local storage can grow; an explicit archival/retention policy is needed before larger runs |
| Quarantine malformed SaaS records while continuing valid records, and refuse publication for a conflicting latest revision | A bad export row should be visible without discarding independent valid rows; a same-revision conflict has no safe winner | This is a synthetic local rule; a later valid higher revision can resolve an older conflict |
| Aggregate SaaS invoices at customer-period grain before joining usage | Several legitimate invoice IDs must not multiply observed usage | Multiple prices or currencies produce an explicit exception; expected amount is null when pricing is ambiguous |
| Scope local backfill to a domain's dated report grain and retain prior generations | Repairs should change the requested period or daily dates without rewriting unrelated report rows | Construction invoice and freshness products are global and recompute; local runs now serialize per root, but independent hosted jobs do not share a distributed lock |
